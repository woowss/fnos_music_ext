## 5. 过程中的错误与纠正（如实记录）

1. **标签指向错误导致漏合**：首次合并把 `snapshot/pre-212-worktree` 当作「我方」，但该标签创建于快照提交之前，指向 `cf843a4`（不含 92 项未提交改动）。结果 2.12 基线漏掉我方 74 个新增文件（全部评审报告/证据文档/候选脚本）与 18 个修改。
   - **发现方式**：核对 `scripts/verify_position_file_evidence.py` 等关键产物在新树中缺失。
   - **修复**：以 `git diff cf843a4..2d35f63 --binary` 生成补丁并在新分支 `git apply --3way` 完整补入（94 文件，零冲突），提交 `91bd9c5`；node 测试从 178 增至 193 全过。
   - **后续动作**：在旧仓库新增标签 `snapshot/pre-212-final` 指向 `2d35f63`，避免再次误用。
2. **CRLF/ LF 混合**：我方旧仓库 318 个文本文件为 CRLF，上游 LF。未规范化前 `sh`/`dash` 解析 `container/env_flag.sh` 直接报 `syntax error near unexpected token '('`（已用纯净树对照确认非代码问题）。规范化后消除。
3. **环境噪声与真实回归的区分**：本地 Windows 的 container 测试大量失败，先在**纯净 v2.12.0** 上跑同款测试取得基线（20 failed / 13 passed / 3 errors），再逐项比对，确认我方新增测试 `test_export_source_env_exports_playlist_manifest_readonly` 在迁移前就因 MSYS `sh` 解析缺陷失败，不是迁移回归。
