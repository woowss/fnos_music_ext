## 2. 方法

3. **三方合并**：`git merge-tree --write-tree --merge-base=v2.10.2 <ours> v2.12.0`，得到合并树 `4402a804`；`git read-tree --reset -u` 落到新工作区。
4. **解决冲突**：15 个文件 22 处，全部人工解决（工具 `scripts/resolve_merge_conflict.py`，UTF-8 安全）。
5. **规范化**：文本文件 CRLF → LF。**准确来源（已用 blob 校验）**：旧仓库快照提交 `2d35f63` 的 337 个文本 blob **全部是 LF（0 个 CRLF）**，所以「我方旧仓库以 CRLF 提交」这一说法不成立；真实原因是**旧工作树的磁盘文件**有 203 个为 CRLF（`git ls-files --eol` = `i/lf w/crlf`），合并后首次 `git add -A`（`2bb9f66`）把其中 **106 个 blob** 写成 CRLF；规范化提交 `eae2882` 把这 106 个改回 LF。当前新树 `git ls-files --eol` 全为 `i/lf w/lf`，tracked CRLF = 0。
6. **回归对齐**：修正合并引入的 5 处行为回归（见 §4）。

### 6.2 附：guard 保护测试暴露的真实合并缺陷（第二轮补测）

统一 runner（`scripts/run_tests.py --suite proxy`）会为 proxy 套件注入隔离环境，因此 3 个被 guard 保护的测试文件只有在 runner 下才真正执行。第二轮补测发现 **8 个失败全部来自 `proxy/tests/test_maintenance_startup.py`**，其中：

1. **真实代码缺陷（已修）**：上游 2.12 把 `detect_library_dir()` / `_drop_privileges()` 放进 `lifespan` 且**无条件执行**；合并后维护模式（`FNMUSIC_MAINTENANCE_STARTUP=1`）进程也会降权 → 后续特权维护操作会因权限不足失败。修复：两者用 `if not maintenance_startup:` 包住（正常模式行为与上游一致）。
2. **测试期望需对齐新基线（已修）**：`library_directory_detection` / `privilege_drop` 属于「启动必经步骤」，不随 `FNMUSIC_BACKGROUND_JOBS` 关闭而跳过（上游安全修复语义）。测试矩阵已更新为：非维护模式必须探测+降权（jobs 开关不影响），维护模式两者都禁止；探针子进程改为 stub `_drop_privileges` 只记录事件，避免测试里真的降权。

修复后：`test_maintenance_startup.py` + `test_maintenance_readiness.py` + `test_webui_gateway.py` 共 **129 passed / 1 skipped**。

> 教训：只用 `pytest proxy/tests` 裸跑会因 guard 跳过这 3 个文件；**必须用统一 runner 才能覆盖**。
