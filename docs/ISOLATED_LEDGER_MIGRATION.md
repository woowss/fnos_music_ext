# Isolated manual-save ledger migration candidate

This utility no longer accepts database paths or writes migration artifacts to a filesystem directory. Its only interface is an inherited connected Unix `SOCK_SEQPACKET` socket. It accepts one fully sealed snapshot descriptor and returns two fully sealed anonymous memory-file descriptors through `SCM_RIGHTS`.

## Protocol

A trusted caller must create a connected `AF_UNIX` `SOCK_SEQPACKET` socket pair and pass one endpoint to the worker as `--socket-fd N` (for example, using `subprocess.Popen(..., pass_fds=(fd,))`). The caller sends one packet containing exactly `MIGRATE_V1_SQLITE_BACKUP_API_COMPLETE` and exactly one `SCM_RIGHTS` descriptor. That packet is only a caller assertion; the worker cannot prove the snapshot's provenance or completeness. Before sending it, the trusted caller must create a consistent snapshot with SQLite's backup API, close the backup, and independently check that the snapshot has no unresolved WAL/journal sidecars. Never copy a live database's main file and submit it as a backup. The descriptor must be a regular file between 1 byte and 64 MiB with `F_SEAL_WRITE`, `F_SEAL_GROW`, `F_SEAL_SHRINK`, and `F_SEAL_SEAL` all set. The worker reads it with `pread` and rechecks its size and seals.

On success, the worker replies with one JSON packet and two `SCM_RIGHTS` descriptors in this order:

1. The original v1 database bytes, unchanged.
2. The v2 candidate database.

The report includes hashes, byte counts, aggregate row counts, and an unverified gate for the trusted caller's SQLite-backup assertion and snapshot consistency. A request string cannot prove the assertion true. It contains no job rows, song metadata, paths, or credentials. Both returned descriptors are sealed against writing, growth, shrinkage, or adding/removing seals, and the worker verifies their contents before handoff. The receiver must independently validate the packet, descriptor count, seals, lengths, and hashes. It owns any later persistence decision; this utility does not write them to disk.

A rejected request receives a fixed `BLOCKED` JSON response without output descriptors when the socket is usable. The worker also exits nonzero. If the peer closes or the socket itself is invalid, no success artifact is sent.

## What the utility validates

The worker deserializes the snapshot into an in-memory SQLite database, validates the exact v1 application ID/schema/content/integrity/foreign keys, and refuses queued, running, `commit_unknown`, `published_cleanup_pending`, or any `cleanup_pending=1` position. It migrates in one transaction, validates the v2 schema/content, compares all jobs and positions, and requires `position_details` to be empty. It then serializes and reopens the v2 database in memory before creating sealed outputs.

The original and candidate exist only as anonymous sealed descriptors. The worker creates no output directory, temporary database, or named migration file. It cannot overwrite or be redirected to an existing path through a `mkdir`/`open` race.

## External gates remain

The caller must obtain a consistent SQLite backup through an independently trusted process after stopping and accounting for every production writer. Never submit a copied live main database file; committed WAL content and snapshot consistency cannot be inferred from a sealed main-file descriptor. Sealing a descriptor proves its bytes cannot change after sealing; it does not prove that the backup was consistent, generated by SQLite's backup API, free of unresolved sidecars, or taken after writers stopped. The protocol token is only an external caller attestation, not proof. A trusted receiver must safely persist the returned descriptors. This utility does not prove receiver isolation, durable persistence, restore behavior, service lifecycle, identity-header provenance, deployment, or rollback. A successful handoff is only an offline migration candidate and does not authorize use against a production ledger.

## Tests

Run semantic and rejection tests:

```sh
python3 -B -m unittest offline_tests.test_migrate_ledger_snapshot -v
```

The Linux-only integration tests create real memfds, seals, socket pairs, and `SCM_RIGHTS` handoffs. They must run on a supported Linux host; Windows skips those tests and does not establish native descriptor behavior. No NAS or live database is used by the tests.
